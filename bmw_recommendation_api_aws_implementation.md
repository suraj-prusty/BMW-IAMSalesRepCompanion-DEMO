# BMW Recommendation API — AWS Implementation Documentation

## 1. Purpose

This document captures the AWS resources, DynamoDB design, Lambda implementation, API Gateway configuration, routes, IAM requirements, and application behavior implemented for the BMW Recommendation API.

This document intentionally excludes the manual testing steps/results performed during implementation.

The document is intended to be provided to GitHub Copilot so it can align the application code with the implemented AWS backend.

## 3. DynamoDB

### Table

```text
Table Name: bmw_recommendation
Region: eu-central-1
Capacity Mode: On-Demand
```

### Primary Key

Partition key:

```text
recommendation_id
Type: String
```

There is no DynamoDB sort key on the base table.

### GSI1

```text
Index Name: GSI1
Partition Key: save_batch_id
Type: String
Sort Key: rank
Type: Number
```

Purpose:

Retrieve all recommendations generated as part of a particular save batch, ordered by recommendation rank.

Example logical query:

```text
save_batch_id = sb-DE-2026W41
```

### GSI2

```text
Index Name: GSI2
Partition Key: rep_period
Type: String
Sort Key: rank
Type: Number
```

Purpose:

Retrieve recommendations for a particular sales representative and planning period, ordered by rank.

The `rep_period` value is generated by Lambda:

```text
{sales_rep_id}#{planning_period_label}
```

Example:

```text
marcus.schmidt#2026-W41
```

## 4. DynamoDB Item Structure

A recommendation item follows this general structure:

```json
{
  "recommendation_id": "string",
  "dealer_id": "string",
  "sales_rep_id": "string",
  "planning_period_label": "string",
  "planning_period_start": "string",
  "planning_period_end": "string",
  "rep_period": "string",
  "save_batch_id": "string",
  "rank": 1,
  "dealer_sales": 100000,
  "carry_over_count": 0,
  "rep_action": "RECOMMENDED",
  "action_at": null,
  "action_by": null,
  "market": "DE",
  "manager_id": "string",
  "account_type": "DEALER",
  "generated_at": "ISO-8601 timestamp",
  "selected_kpis_json": {}
}
```

### Important derived field

The application should not require the caller to calculate `rep_period`.

Lambda derives it automatically:

```python
rep_period = f"{sales_rep_id}#{planning_period_label}"
```

This is required for GSI2.

## 8. Lambda JSON Serialization

DynamoDB returns numeric values as `Decimal`.

The Lambda converts integer-like Decimal values to JSON integers and fractional Decimal values to JSON floats.

Implementation:

```python
def decimal_serializer(obj):
    if isinstance(obj, Decimal):
        if obj % 1 == 0:
            return int(obj)
        return float(obj)
    raise TypeError(f"Type {type(obj)} not serializable")
```

Common API response wrapper:

```python
def response(status_code, body):
    return {
        "statusCode": status_code,
        "headers": {
            "Content-Type": "application/json"
        },
        "body": json.dumps(
            body,
            default=decimal_serializer
        )
    }
```

## 9.6 Update Recommendation

Function:

```text
update_recommendation(recommendation_id, data)
```

Operation:

```text
DynamoDB UpdateItem
```

The API intentionally uses an allowlist of fields that can be updated.

Allowed fields:

```text
rep_action
action_at
action_by
carry_over_count
```

The following fields should not be modified through the update API:

```text
recommendation_id
dealer_id
sales_rep_id
planning_period_label
planning_period_start
planning_period_end
rep_period
save_batch_id
rank
dealer_sales
generated_at
selected_kpis_json
market
manager_id
account_type
```

The update uses:

```text
UpdateExpression
ExpressionAttributeNames
ExpressionAttributeValues
ReturnValues = ALL_NEW
```

The API returns the complete updated item.

Success HTTP status:

```text
200
```

# 18. IAM Requirements

The Lambda execution role must have permission to perform the following DynamoDB operations:

```text
dynamodb:PutItem
dynamodb:BatchWriteItem
dynamodb:GetItem
dynamodb:Query
dynamodb:UpdateItem
```

These permissions should be scoped to the recommendation table:

```text
arn:aws:dynamodb:eu-central-1:245439046166:table/bmw_recommendation
```

For GSI queries, the IAM policy should also allow access to the table indexes, for example:

```text
arn:aws:dynamodb:eu-central-1:245439046166:table/bmw_recommendation/index/*
```

The Lambda execution role also requires normal Lambda logging permissions if CloudWatch logging is desired, typically:

```text
logs:CreateLogGroup
logs:CreateLogStream
logs:PutLogEvents
```

# 21. Application Integration Contract

The application should treat the AWS backend as the recommendation persistence/API layer.

Recommended logical flow:

```text
Recommendation Generation
        |
        v
POST /recommendations
        |
        v
DynamoDB: bmw_recommendation
        |
        +---- GSI1: save_batch_id + rank
        |
        +---- GSI2: rep_period + rank
        |
        v
Sales Rep / Manager Application
        |
        +---- GET recommendation
        |
        +---- GET batch recommendations
        |
        +---- GET rep-period recommendations
        |
        +---- PUT recommendation action
```

# 22. Important Implementation Rules for Copilot

When modifying the application:

1. Use `recommendation_id` as the unique recommendation identifier.
2. Do not calculate or persist a different representation of `rep_period`.
3. Always derive `rep_period` as:

```python
f"{sales_rep_id}#{planning_period_label}"
```

4. Treat `rank` as a numeric value.
5. Treat `dealer_sales` as numeric.
6. Treat `carry_over_count` as numeric.
7. Use `GSI1` for batch-based retrieval.
8. Use `GSI2` for sales-representative/planning-period retrieval.
9. Do not expose arbitrary DynamoDB field updates from the frontend.
10. PUT updates should be restricted to:

```text
rep_action
action_at
action_by
carry_over_count
```

11. Do not expose DynamoDB credentials or AWS credentials in frontend code.
12. The frontend should communicate with the API Gateway endpoint, not directly with DynamoDB.
13. Keep the API Gateway URL configurable through application configuration/environment variables rather than hardcoding it throughout the application.
14. The API currently uses the `$default` API Gateway stage with auto-deployment.
15. The backend region is `eu-central-1`.

- Cognito/JWT authentication
- Frontend implementation
- CORS configuration
- EventBridge weekly reconciliation
- Scheduled Lambda reconciliation
- Weekly carry-over automation
- Manager-specific authorization rules
- Sales-rep-specific authorization rules
- DynamoDB Streams
- CloudFront
- WAF
